# tmux-workspace public v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make tmux-workspace installable and usable by anyone on macOS or Linux, add a curses agent dashboard on `Ctrl+a A`, and prove it all with tests, a distro install matrix and CI.

**Architecture:** Pure logic moves into small stdlib modules under `lib/` (`paths`, `workspace_model`, `dashboard`). The controller `bin/tmux-workspace` calls them, following the `cleanup(globals())` pattern. Platform differences live in two tiny POSIX `sh` helpers (`tw-clip`, `tw-sound`) and in `install.sh`. Tests stay on stdlib `unittest`; tmux behaviour is tested on scratch servers that never load the user's config.

**Tech Stack:** Python 3.9+ stdlib (curses, dataclasses, unittest), tmux, POSIX sh, bash 3.2, Docker (install matrix), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-05-public-v1-design.md`

## Global Constraints

- No third-party Python packages. Runtime code (`bin/`, `lib/`, `integrations/agent-hook.py`, `scripts/`) must compile and run on Python 3.9 (`/usr/bin/python3 -m py_compile <file>`). Tests may use 3.11+ APIs such as `enterContext`.
- `install.sh` runs on bash 3.2: no associative arrays, no `mapfile`, no `${var,,}`, no `|&`. It passes `shellcheck`. `bin/tw-clip` and `bin/tw-sound` are POSIX `sh`.
- Platforms: macOS first-class; Linux supported (Ubuntu 24.04, Debian 12, Fedora, Arch, Alpine 3.20).
- Status colours (exact): blocked `#f7768e` bold, done `#7dcfff`, working `#e0af68`, idle `#9ece6a`. Marks: `●` for blocked/done/working, `○` for idle. Roll-up order: blocked, done, working, idle.
- Shells that count as "no agent running": `zsh bash fish sh dash ksh tcsh`, with or without a leading `-`.
- License: MIT, `Copyright (c) 2026 Ahmed Khatab`.
- The author's live setup is symlinked to this repo. Never reload the author's running tmux server from a test. Every tmux test uses `tmux -L <unique> -f /dev/null` and a temporary `TMUX_WORKSPACE_STATE_DIR`.
- One commit per task on `feat/public-v1`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push.

## Review Focus

1. Labels or workspace names with wide characters (CJK, emoji): dashboard columns must stay aligned and every line must be exactly the terminal width in display cells. Test in Task 6.
2. The dashboard run outside tmux or with no server: one clear line on stderr, exit status 1, no traceback. Test in Task 7.
3. `install.sh` when `~/.tmux.conf` is already a symlink into this same clone (the author's case): no backup is made and the second run reports "already installed". A link to a different location is backed up. Test in Task 10.
4. `~/.zshrc` that is itself a symlink (stow, chezmoi): the installer edits the link target and leaves the symlink in place. Test in Task 10.
5. `$SHELL` unset or pointing at a missing binary when a pane starts: the pane gets `/bin/sh`, never a dead pane. Test in Task 3.
